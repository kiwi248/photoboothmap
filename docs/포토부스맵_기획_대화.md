## 1. 기획 평가

**문제의식 자체는 타당해요.** 네이버·카카오 지도에서 "사진"으로 검색하면 스튜디오·사진관이 섞여 나오는 건 실제로 불편한 지점이고, 인생네컷/포토이즘/하루필름/셀픽스처럼 브랜드가 파편화돼 있어서 "내 주변 포토부스만" 보여주는 지도는 수요가 있는 아이디어예요.

**다만 이미 비슷한 서비스가 여러 개 나와 있어요.**
- 네컷맵(4cutmap.com) — 정확히 같은 컨셉으로, 인생네컷·포토이즘·하루필름·셀픽스 등 브랜드별 위치를 지도에서 보여주고 길찾기까지 연결되는 서비스예요.
- 포토부스-인생네컷, 포토이즘, 하루필름 등 찾기 — 앱스토어/플레이스토어에 있는 개인 개발자 앱. 위치 기반 검색 + 거리순 정렬 + 네이버맵/카카오지도 연동. 다만 다운로드 100+ 수준으로 아직 작은 규모예요.
- PICSEL — 포토부스 검색 + 네컷사진 보관 앱.
- GitHub에도 "네컷 지도"라는 오픈소스 프로젝트 조직이 있고요.

즉 "블루오션"은 아니고, 이미 몇몇이 시도한 니치 시장이에요. 그런데 역설적으로 이건 나쁜 소식만은 아니에요 — ① 시장 검증은 어느 정도 된 아이디어라는 뜻이고, ② 위 경쟁자들 다운로드/트래픽 규모가 다들 작아서 확고한 1등이 없는 상태예요. 다만 그대로 만들면 차별점이 없어서 아래 중 몇 가지는 꼭 고민하고 들어가는 걸 추천해요.

- 사용자 제보/등록 기능 (신규 오픈·폐업 반영 — 포토부스는 임대매장이라 회전이 빨라서, 데이터 신선도가 사실상 이 서비스의 핵심 경쟁력이에요. 기존 앱들엔 이 기능이 잘 안 보였어요)
- 브랜드/컨셉별 필터, 기기별 프레임 미리보기, 가격 정보
- 리뷰·사진 결과물 공유 커뮤니티 요소
- 데이트 코스·핫플 콘텐츠와 결합해서 SEO/바이럴 유입 만들기 (검색만으론 트래픽이 잘 안 붙는 카테고리라)

**현실적으로 중요한 리스크 두 가지:**
1. 초기 데이터 확보 — 브랜드 공식 홈페이지의 "매장 찾기" 페이지를 크롤링/정제해서 시작하는 게 일반적인 방법이지만, 이후 지속적인 운영(폐업 반영 등)이 없으면 곧 낡은 지도가 돼요.
2. 로고·상표 사용 — 브랜드명/로고를 지도에 표기할 때 상표권 관련해서 과도한 사용(로고 이미지 그대로 사용 등)은 피하는 게 안전해요.

포트폴리오 관점에서는 지도 API 연동, 지리공간 DB 설계, 크롤링/데이터 정제, 배포까지 다뤄볼 수 있어서 백엔드 취업 준비생 입장에선 수익과 무관하게 해볼 가치는 충분히 있어요.

## 2. 추천 기술 스택

**백엔드: FastAPI 추천 (Spring Boot도 가능)**
둘 다 능숙하다고 하셨는데, 이런 소규모 CRUD + 지도 데이터 프로젝트는 FastAPI가 개발 속도 면에서 유리해요. Pydantic으로 스키마 검증이 쉽고, SQLAlchemy + GeoAlchemy2로 PostGIS 연동도 깔끔해요. 다만 취업 시즌에 "정통 백엔드"(Spring) 포트폴리오가 더 필요하다고 판단되면 Spring Boot로 가도 무리 없어요 — 이 프로젝트 규모에선 기술 선택보다 "완성해서 배포까지 했는가"가 더 중요해요.

**프론트엔드: Vite + React (SPA)로 가볍게 시작 추천**
React를 한 번만 다뤄보셨다니, 처음부터 Next.js(SSR)까지 가면 학습 곡선이 부담될 수 있어요. 지도 중심 앱은 SPA로도 충분하니 Vite + React + 카카오맵 JS SDK로 시작하고, 나중에 SEO가 정말 중요해지면(검색 유입을 늘리고 싶을 때) Next.js로 옮기는 걸 추천해요.

**지도 API: 카카오맵 API**
무료 할당량이 넉넉해요 (지도 API 일 30만 호출, 로컬(장소검색) API 일 10만 호출, 통합 월 300만 호출). 초기 트래픽에서는 사실상 무료로 충분합니다.

**DB: PostgreSQL + PostGIS**
"내 주변 포토부스" 같은 반경 검색을 하려면 PostGIS 확장이 붙은 Postgres가 정석이에요. Render의 무료 Postgres는 용량이 작고(256MB) 90일 후 만료되는 정책이 있으니, 처음부터 Supabase 무료 티어(500MB, PostGIS 기본 지원)를 쓰는 것도 좋은 대안이에요.

**배포: Render(백엔드) + Vercel(프론트엔드) — 다만 한 가지 주의할 점**
Vercel Hobby(무료) 플랜은 공식 약관상 "비상업적 개인 용도"로 제한돼 있어요. 애드센스 광고를 붙이는 게 엄밀히는 상업적 이용에 해당할 수 있어서, 규모가 작을 때는 실제로 문제 삼는 경우는 드물지만 완전히 안전하진 않아요. 트래픽이 커지거나 신경 쓰인다면 Vercel Pro($20/월)나, 정적 SPA라면 Cloudflare Pages(상업적 이용 제한이 상대적으로 느슨함) 같은 대안도 고려해볼 만해요.

## 3. 비용 추정

**개발 비용**: 혼자 개발하신다면 현금 지출은 거의 없고, 시간이 비용이에요. MVP(지도+검색+필터+기본 데이터) 기준으로 주말/방과후 작업이면 대략 4~8주 정도로 보는 게 현실적이에요. 초기 데이터 수집(크롤링+정제)이 생각보다 시간을 많이 잡아먹는 구간이니 일정에 여유를 두시는 걸 추천해요.

**유지보수 월 비용 (초기 트래픽 기준)**

| 항목 | 무료로 시작 가능 | 유료 전환 시 |
|---|---|---|
| 도메인(.com) | - | 약 1,000~1,500원/월 (연 1.5만원 내외) |
| 백엔드(Render) | 무료 티어 (단, 비활성 시 슬립 → 첫 요청 지연 발생) | Starter $7/월(약 9,500원) — 상시 구동 원하면 |
| DB(Supabase/Render) | 무료 티어(500MB 내외) | $25/월~ (Supabase Pro) |
| 프론트(Vercel) | 무료(Hobby) | Pro $20/월 — 상업적 이용 명확히 하려면 |
| 카카오맵 API | 무료(할당량 내) | 거의 도달하지 않을 가능성 높음 |
| SSL | 무료(자동 발급) | - |

정리하면 완전 무료로도 서비스는 가능하고 (도메인만 연 1.5만원 정도), 사용자가 늘어나 백엔드 상시 구동이 필요해지는 시점엔 월 1만~3만원 선으로 보시면 돼요.

**애드센스 수익 현실성**: 솔직하게 말씀드리면, 이런 니치 로컬 서비스는 초기 트래픽이 작아서 애드센스 수익은 처음엔 거의 미미할 가능성이 높아요(월 몇천~몇만원 수준도 트래픽이 꽤 붙어야 나와요). 수익화보다는 "포트폴리오 + 트래픽/SEO 실험"으로 접근하시고, 수익은 보너스 정도로 기대치를 잡는 걸 추천해요. 그리고 애드센스 수익이 실제로 발생하면 (사업자등록 자체는 필수는 아니지만) 종합소득세 신고 의무는 생길 수 있어요 — 이 부분은 저는 세무 전문가가 아니니 규모가 커지면 세무사나 국세청 홈택스 상담을 받아보시길 권해요.

## 대화 2

**키위:**

인생네컷, 포토이즘, 하루필름같은 곳의 위치는 지도API에서 불러올 수 없는 거야? 브랜드 공식 홈페이지에서 크롤링해야 하는 거야?

**Claude:**

찾아보니 핵심 사실은 이거예요.

카카오맵 키워드 검색으로 "인생네컷" 검색하면 매장들이 나오긴 해요. (실제로 일반 카카오맵 앱에서 검색해보면 나옵니다.) 인생네컷 공식 홈페이지에도 매장안내(https://lifefourcuts.com/Store01) 페이지가 따로 있고요. 문제는 그 검색 결과를 "가져다 쓸 수 있느냐"예요.

카카오 로컬 API(키워드 장소검색)로 장소명/주소를 조회할 수는 있지만, 그 결과를 DB에 저장하는 건 약관상 금지되어 있어요. 카카오 개발자 포럼의 공식 답변을 보면:

> API 결과값인 장소명, 주소 등 콘텐츠 데이터를 DB에 저장하는 것은 (캐시 목적에 해당하지 않아) 정책상 허용되지 않습니다.

저장 가능한 건 장소 ID와 카카오맵 상세페이지 URL 정도이고, 이름·주소 같은 실제 콘텐츠는 매번 API를 실시간 호출해서 화면에 뿌려야 해요. 즉 이 API는 "우리 서비스가 자체 DB에 포토부스 목록을 구축"하는 용도로는 못 써요. 매번 카카오에 물어보는 프록시 역할 정도만 가능한 거죠. 이러면 "인생네컷만", "포토이즘만" 골라서 필터링하는 것도 어려워지고(키워드 검색은 카카오가 분류한 결과를 그대로 받는 거라 브랜드별 정제가 힘듦), 서비스의 핵심인 "우리만의 큐레이션된 DB"를 만들 수가 없어요.

추가로 확인된 것: 카카오맵 웹/앱에 보이는 모든 장소가 API로 제공되는 것도 아니에요("팝업스토어 등은 카카오 내부 정책에 따라 API 제공 대상에서 제외될 수 있다"는 공식 답변도 있었어요). 포토부스처럼 소형 임대매장 위주인 업종은 이런 누락 가능성도 염두에 둬야 해요.

**그래서 결론적으로:**

1. 초기 데이터는 브랜드 공식 홈페이지 매장안내 페이지에서 수집(크롤링/파싱)하는 게 맞아요. 인생네컷, 포토이즘 등 대부분 브랜드가 "매장찾기" 페이지를 공식 제공하니(예: lifefourcuts.com/Store01), 여기서 매장명·주소를 가져와 지오코딩(주소→좌표 변환)해서 자체 DB에 저장하는 방식이에요.
2. 좌표 변환(주소→위경도)엔 카카오 로컬 API를 써도 돼요. "장소 검색" 결과를 저장하는 게 문제이지, 카카오가 제공하는 주소 검색(좌표 변환) API로 좌표값 자체를 얻어서 저장하는 건 통상적인 지오코딩 용도라 문제 소지가 적어요 (좌표는 카카오의 "콘텐츠 데이터"라기보다 변환 결과값에 가까움 — 다만 이 부분도 애매하면 카카오에 직접 문의하는 걸 추천해요).
3. 지도에 마커를 뿌리는 건 카카오맵 JS SDK(지도 표시용)를 그대로 쓰면 되고, 이건 DB 저장 문제와 무관해요 — 화면에 지도 타일과 마커를 그리는 용도라 제약이 없어요.
4. 지속적인 데이터 최신화는 결국 크롤링 자동화(주기적 재수집) + 사용자 제보 시스템 조합이 현실적이에요. 공식 매장안내 페이지를 정기적으로 다시 긁어서 diff 비교(신규/폐업 감지)하는 배치 작업을 만드는 걸 추천드려요.

한 가지 유의점: 브랜드 공식 홈페이지 크롤링도 그 사이트의 robots.txt나 이용약관을 확인하는 게 안전해요. 대부분 "매장찾기" 페이지는 고객이 보라고 공개한 정보라 크롤링 리스크가 낮은 편이지만, 상업적 재배포(광고 붙여서)로 쓰는 거라 완전히 문제없다고 단정하긴 어려워요 — 법률 자문은 아니니 참고만 해주세요.

## 대화 3

**키위:**

그럼 나중에 매장들이 폐업하거나 신규 오픈할 수도 있잖아. 그러면 매번 브랜드 홈페이지 가서 크롤링 해야 돼?

**Claude:**

네, 기본적으로는 "주기적으로 다시 크롤링해서 비교"하는 방식이 맞아요. 다만 매번 수동으로 가는 게 아니라 자동화하면 되고, 여기에 사용자 제보를 더하면 정확도가 훨씬 올라가요. 정리하면 이렇게 구성하는 걸 추천해요.

**1) 정기 크롤링 배치 작업 (자동화)**

매번 직접 브랜드 홈페이지에 가는 게 아니라, 스케줄러(cron)로 주기적으로 자동 재수집하는 구조를 만들면 돼요.

- FastAPI를 쓰신다면 APScheduler나 Celery beat, 또는 그냥 Render의 Cron Job 기능(Render에 Cron Job 서비스가 따로 있어요, 유료지만 저렴)으로 "매일 새벽 1회 각 브랜드 매장안내 페이지 재크롤링" 작업을 돌리는 거예요.
- 크롤링한 최신 목록과 기존 DB를 diff 비교해서: 새로 생긴 주소는 "신규 후보"로, DB엔 있는데 최신 크롤링에서 안 보이는 주소는 "폐업 후보"로 플래그만 달아둬요. 바로 자동 삭제/추가하지 않고 후보 상태로 큐에 쌓아두는 게 안전해요 (홈페이지 개편이나 일시적 오류로 목록이 바뀌는 경우도 있어서, 자동으로 바로 반영하면 오히려 데이터가 깨질 수 있어요).
- 이 후보들을 관리자(본인)가 주기적으로 확인해서 승인하는 간단한 관리자 페이지/엔드포인트를 만들어두면 운영 부담이 크게 줄어요.

**2) 사용자 제보 기능 (크라우드소싱)**

크롤링만으론 한계가 있어요 — 브랜드가 홈페이지를 잘 관리 안 하거나, 실제 폐업했는데 홈페이지엔 계속 남아있는 경우도 흔하거든요. 그래서:

- "여기 폐업했어요" / "새로 생긴 매장이에요" 신고 버튼을 지도에 붙이고,
- 신고가 일정 횟수(예: 3명 이상) 쌓이면 자동으로 "비활성" 처리하거나 관리자 검토 큐에 올리는 식으로 설계하면, 실제 방문자들이 지도를 최신 상태로 유지해주는 효과가 있어요. (이게 사실 경쟁 서비스들에 없어 보였던 차별점이기도 하고요.)

**3) 데이터 신선도 표시**

각 매장 데이터에 "최종 확인일"을 붙여서 사용자에게 보여주는 것도 좋아요. "3일 전 확인됨" 같은 식으로요. 이러면 오래된 정보에 대한 사용자 신뢰 문제도 줄고, 오래된 항목을 우선적으로 재검증하는 로직도 짤 수 있어요(예: 30일 이상 미확인 매장은 다음 크롤링 때 우선순위로 재확인).

**운영 부담 현실적으로 보면**

처음엔 브랜드가 몇 개 안 되니(인생네컷, 포토이즘, 하루필름, 셀픽스 정도로 시작) 크롤러 몇 개만 만들면 되고, 한 번 자동화 파이프라인을 짜두면 이후엔 관리자 페이지에서 승인/거절 클릭만 하면 되는 수준이라 유지보수 부담이 크진 않을 거예요. 다만 브랜드 홈페이지가 구조를 바꾸면(HTML 마크업 변경) 크롤러가 깨질 수 있으니, 크롤러 실패 시 알림(예: 크롤링 결과가 0건이거나 이전 대비 급감하면 텔레그램/이메일로 본인에게 알림)을 넣어두는 걸 추천해요.

스크린샷 보니까 네컷맵은 브랜드 필터(15개+), 반경 검색, 검색바까지 이미 잘 갖춰놨네요. 이 정도면 "위치 찾기"라는 핵심 기능 자체로는 따라잡기보다, 네컷맵에 없는 걸 파는 전략이 맞아요. 검색해보니 이 시장에 "네컷모아", "PICSEL"처럼 포토부스 지도 + 네컷사진 보관/앨범 정리를 묶은 서비스들도 있긴 하지만, 아직 확실한 승자는 없어 보여요. 사용자님의 원래 문제 상황("친구랑 새로운 동네 가서 사진 찍으려고")으로 돌아가서 생각해보면 이런 것들이 진짜 차별점이 될 수 있어요.

**1순위로 추천하는 기능 — 친구와 함께 고르기**

- 지도에서 후보 찍어서 링크 하나로 친구한테 공유 (카톡 공유 버튼)
- 친구가 링크 열면 로그인 없이 바로 후보들 보고 투표/이모지 반응만 남기는 방식
- "이 근처에서 만나자" 하면 중간지점 계산해서 그 근처 포토부스 추천

이건 회원가입/로그인 시스템도 최소화할 수 있어서(익명 세션 URL 방식) 개발 난이도도 과하지 않고, 다른 앱들이 안 하고 있는 영역이라 차별점이 뚜렷해요.

**2순위 — 프레임(컨셉) 미리보기**

포토부스는 지점마다/시즌마다 사용 가능한 프레임 디자인이 다르고(콜라보 프레임, 시즌 한정 프레임 등), 이게 실제로 사람들이 "어디 갈지 정할 때" 되게 중요하게 보는 정보예요. "이 지점엔 지금 어떤 프레임 있음" 사진을 지점별로 보여주면, 단순 위치 지도가 아니라 "어디 갈지 결정하는 도구"로 격상돼요. 브랜드 공식 SNS/홈페이지에서 신규 프레임 소식을 수집해서 태깅해두는 식으로 시작할 수 있어요.

**3순위 — 사용자 제보 + 실사용 리뷰**

이전에 얘기했던 폐업/신규 반영용 제보 기능을 아예 "리뷰" 기능으로 확장하는 거예요. 예를 들어 "청결도", "소품 상태", "혼잡도(체감)", "최근 방문일" 같은 짧은 태그형 리뷰. 스크린샷상 네컷맵에는 이런 사용자 참여형 데이터가 안 보였고, 이게 앞서 얘기한 "데이터 신선도" 문제도 동시에 해결해줘요 — 리뷰가 최근에 달렸다는 것 자체가 "이 지점 아직 영업 중"이라는 신호가 되거든요.

**그 외 고려해볼 만한 것들 (우선순위는 낮지만 부담 적음)**

- 인원수/부스 크기 필터 (2인용/4인용 이상 구분 — 단체 모임 시 유용)
- 영업시간·결제수단(카드/모바일페이 가능 여부) 표시
- 즐겨찾기 + "나중에 가볼 곳" 리스트 저장

## 데이터 모델

포토부스 프레임은 대부분 매장 단위가 아니라 브랜드 단위로 공통 배포돼요(전국 인생네컷 매장이 같은 시즌 프레임을 동시에 씀). 다만 팝업/콜라보 매장은 그 매장에서만 특정 프레임을 쓰기도 하니, 이 예외 케이스만 nullable로 열어두면 돼요.

```
Brand (id, name, logo_url)

Frame (
  id,
  brand_id (FK),
  store_id (FK, nullable — 특정 매장 전용 콜라보 프레임일 때만 값 있음),
  title,
  thumbnail_url,
  category (시즌/콜라보/베이직/기념일),
  tags (예: "크리스마스", "곰돌이", "커플용"),
  is_active,
  first_seen_at
)
```

매장 상세 화면에서는 `해당 브랜드의 Frame 전체 + store_id가 그 매장인 Frame`을 합쳐서 보여주면 브랜드 공통 프레임과 매장 한정 프레임을 자연스럽게 같이 노출할 수 있어요.

## 데이터 수집 — MVP는 자동화보다 수동 큐레이션 추천

여기가 사실 제일 현실적인 고민 지점이에요. 신상 프레임 정보는 주로 브랜드 공식 인스타그램에 제일 빨리 올라와요. 근데 인스타그램은 로그인 없이 크롤링이 제한적이고 API도 비즈니스 인증이 까다로워서, MVP 단계에서 자동화하려다 시간을 다 쓰게 될 가능성이 높아요.

그래서 처음엔 본인이 직접 확인해서 관리자 페이지에서 업로드하는 수동 큐레이션으로 시작하는 걸 추천해요. 구체적으로:

1. 브랜드별 인스타그램을 주 1~2회 직접 확인 (브랜드 수가 적으면 부담 크지 않아요)
2. 신상 프레임 캡처 → 간단한 관리자용 업로드 폼(FastAPI에 인증 걸린 엔드포인트 하나, 프론트는 대충 만들어도 됨)에서 브랜드/카테고리/태그 지정 후 등록
3. 데이터가 쌓이고 트래픽이 늘면 그때 Instagram Graph API나 브랜드 홈페이지 크롤링 자동화를 검토

수동이라고 해서 나쁜 선택이 아니에요 — 오히려 초반엔 "직접 확인한 정확한 정보"라는 신뢰도를 만드는 데 더 유리하고, 나중에 자동화로 넘어가기도 쉬워요.

## 이미지 저장소

Render의 디스크는 배포할 때마다 초기화되는 ephemeral 스토리지라 이미지를 거기 저장하면 안 돼요. Cloudflare R2를 추천드려요 — 무료 티어가 10GB 저장 + egress(다운로드 트래픽) 완전 무료라서, 이미지 위주 서비스엔 딱 맞아요(S3 계열은 보통 egress 과금이 나가는 게 부담인데 R2는 그게 없어요). 업로드할 때 Pillow로 원본은 R2에 두고 썸네일(작은 사이즈)을 하나 더 만들어서 목록 화면 로딩을 가볍게 하는 것도 같이 해두면 좋아요.

## UI

매장 상세 팝업/페이지에 "이 매장에서 볼 수 있는 프레임" 섹션을 가로 스크롤 썸네일 그리드로 넣고, 카테고리 필터(시즌/콜라보/베이직) 칩을 위에 달아주면 돼요. 클릭 시 확대 모달 정도면 MVP로 충분해요.

## 저작권 관련 유의사항 (중요)

프레임 디자인은 브랜드의 저작물이에요. 몇 가지 리스크를 낮추는 방법은 있어요.

- 원본 고화질이 아니라 저해상도 썸네일만 사용
- 캡처본 그대로(브랜드 워터마크·로고 포함) 사용 — 출처가 명확해져서 오히려 무단 도용처럼 보이지 않고, 브랜드 입장에서도 홍보 효과로 받아들여질 가능성이 높음
- 각 프레임에 "출처: OO 공식 인스타그램" 표기 + 가능하면 원본 게시물 링크 연결
- 브랜드 측에서 삭제 요청이 오면 즉시 대응할 수 있는 연락 창구(이메일 등)를 사이트에 명시

다만 이건 법적으로 100% 안전을 보장하는 방법은 아니고, 실제로 맛집 앱들의 메뉴판 사진처럼 "정보 제공 목적의 인용"으로 널리 통용되는 관행에 가까워요 — 저는 법률 전문가가 아니니 서비스가 커지면 한 번쯤 법률 자문을 받아보시길 권해요.

## 3) React 앱에 실제로 코드 삽입하기

승인되면 애드센스 대시보드에서 광고 단위(디스플레이 광고, 인피드 광고 등)를 만들면 `<ins>` 태그가 담긴 코드를 줘요. React에서는 이런 식으로 컴포넌트화해서 쓰면 돼요.

```jsx
// index.html <head>에 한 번만 삽입
<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXXXXXXXX"
        crossorigin="anonymous"></script>
```

```jsx
// components/AdBanner.jsx
import { useEffect } from "react";

export default function AdBanner({ slot }) {
  useEffect(() => {
    try {
      (window.adsbygoogle = window.adsbygoogle || []).push({});
    } catch (e) {
      console.error(e);
    }
  }, []);

  return (
    <ins
      className="adsbygoogle"
      style={{ display: "block" }}
      data-ad-client="ca-pub-XXXXXXXXXX"
      data-ad-slot={slot}
      data-ad-format="auto"
      data-full-width-responsive="true"
    />
  );
}
```

그리고 원하는 위치(지도 화면 우측 사이드바, 하단 등)에 `<AdBanner slot="1234567890" />` 이런 식으로 배치하면 돼요. SPA 특성상 페이지 전환 시 광고가 다시 로드 안 되는 이슈가 있을 수 있어서, 라우트가 바뀔 때마다 광고 컴포넌트를 새로 mount 시키는 처리(key prop 활용 등)가 필요할 수 있어요.

## 4) 배치할 때 주의할 점

- 지도 마커나 클릭 버튼 근처에 광고를 두면 안 돼요. 실수로 클릭 유도하는 배치(오검 클릭 유발)는 애드센스 정책 위반으로 계정 정지 사유가 돼요. 거지맵도 광고가 지도 콘텐츠 영역과 분리된 사이드/하단에 명확히 배치돼 있죠.
- 모바일 화면에서 광고가 지도 조작을 가리지 않게 반응형으로 배치해야 해요.
- 이전에 말씀드렸던 Vercel Hobby 플랜의 "비상업적 이용" 제한도 여기서 다시 걸려요 — 실제로 광고를 붙여서 수익을 내기 시작하면 상업적 이용에 해당하니, 이 시점에는 Vercel Pro로 올리거나 다른 호스팅을 고려하시는 게 안전해요.

## 5) 현실적인 팁

지도 앱은 애드센스 승인이 텍스트 콘텐츠 위주 블로그보다 조금 까다로운 편이에요. 브랜드별 소개 페이지, "지역별 인기 포토부스" 같은 글 콘텐츠를 같이 만들어서 사이트에 "정보성 콘텐츠"가 충분하다는 인상을 주는 게 승인 확률을 높이는 실질적인 방법이에요.
